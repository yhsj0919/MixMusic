# 集合详情与按需播放

歌单、专辑、歌手和排行榜通过独立路由进入共用歌曲详情页，当前实现放在 `page/playlist/play_list_detail_page.dart`。歌手详情提供歌曲及“查看专辑”入口；只有插件声明 `artistAlbum` 时显示入口。专辑通过 `/artist/albums` 按需分页，点击后进入既有专辑详情。

首页“榜单”进入 `/ranks`：只列出已启用且声明 `rankList` 的音源，默认使用当前音源，不支持时选择首个可用音源。复用首页已有榜单，否则只请求选中音源；切源不批量查询其他插件。失败可重试并查看日志，点击榜单进入 `/rank` 共用详情与播放队列。

MV 使用独立 `/mv` 详情页，从首页与搜索进入，调用插件 `mvInfo` 展示基本信息、主地址和画质列表。成功后自动向控制台与插件日志打印主地址及各画质地址，也可手动再次打印；没有地址只报告“MV 未返回地址”，不推测原因。不接视频播放，不影响当前音乐队列。

## 插件接口

- 歌单调用 `playListInfo`，专辑调用 `albumInfo`；返回基本信息与 `songs`。
- 歌手首次调用 `artistInfo`，歌曲分页调用 `artistSong`。
- 歌手专辑仅在进入专辑列表后调用 `artistAlbum`，每页 20，滚动或点击加载更多；未满一页时停止。专辑与歌曲各自保存页码、结果和错误，同页并发请求合并，离开后保留本次运行期间已加载数据，不预取专辑歌曲，也不改动播放队列。
- 排行榜列表调用 `rankList`，详情分页调用 `rankInfo`，沿用同一套集合加载与队列流程。
- API 边界统一转换为 `Album`、`Artist`、`PlayList`、`Rank`、`Mv`，首页、搜索、路由和详情不再传资源 Map。共用展示字段放在 `MusicResource`，歌曲分页字段放在 `MusicCollection`；动态 ID 原样保留，插件附加字段保存在 `details`，调用插件时通过 `toJson()` 还原。
- 页码从 0 开始，每页 20。优先使用详情返回的 `hasMore`，其次 `total`；未提供时根据当前页条数判断结束，空页停止加载。
- 资源身份仍为插件 ID 加原始动态 ID，不增加资源 type。内部集合类别仅选择对应接口和路由，不写进插件资源身份。
- 首页可使用 `getHome` 的 `playlists`、`albums`、`artists`、`mvs`、`ranks`；缺少分区时，用户点击后才调用插件已声明的对应列表或推荐接口。不支持的分区隐藏。
- 宿主不识别数据来自哪里，不推测登录、会员等失败原因；错误按实际返回显示并记录插件日志。

## 加入队列

2026-10-16：改用独立 [HyperQueue](hyper-queue.md)，统一处理顺序、插入及惰性来源；播放控制器不再维护歌曲来源映射和手工分页插入逻辑。

- 详情首次仅加载一页。“加入播放列表”只登记来源、复用已有内容，不主动请求第一页；“播放全部”才按需展开目标来源，不遍历全部分页。
- 插件控制器在本次运行期间复用集合分页状态；队列订阅已加入集合的新歌曲，离开详情页后仍可续载。
- 查看详情或播放列表时，滚动接近末尾再加载；播放距当前集合已加载末尾两首时预取，到边界等待同一个未完成请求。
- 并发查看与播放请求合并。分页成功才推进页码，失败保留已有数据并停止自动重试，可手动重试。
- 追加单曲或歌单排在完整逻辑队列尾部；A 的新分页只填到 A 内部，不会跑到追加的单曲或 B 后面。“下一首”插入后继续原顺序，支持单曲及整个集合。
- 清空队列、移除集合全部歌曲或停用插件会解除队列订阅。未完成请求仍可为详情提供结果，但不能把已清理的队列填回来。
- 不持久化队列或集合缓存，不在本阶段引入数据库。

## 功能验证

合成 JS 插件验证推荐、四种集合详情、MV、资源列表和动态 ID；控制器测试验证分页去重、预取阈值、失败重试、清空取消、下一首优先级与插件停用。只验证功能，不验证 UI。
