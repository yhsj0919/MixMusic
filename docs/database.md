# 本地数据库、播放历史与下载记录

使用 SQLite / sqlite_async，异步执行 SQL，无 ORM、生成代码或通用 DAO。

- `AppDatabase` 只拥有连接、功能迁移和关闭；事务直接使用 `connection.writeTransaction`。
- 每个功能拥有自己的表和迁移版本表，历史使用 `_history_migrations`。后续修改新增版本，不改已执行的迁移。
- `PlaybackHistoryStore` 独立提供记录、分页读取、删除、清空，不依赖播放器、页面、插件或其他业务 Store。
- `PlayerHistory` 只观察播放状态，进度在播放中前进后记录；失败点击、暂停和启动恢复不记录。
- `main.dart` 是组装点。移除历史观察器、Store 注册和页面入口即可停用历史，不修改播放器；旧表可留存，不自动删除用户数据。

历史按 `pluginId + JSON id` 去重，原始 id 保持动态 JSON 类型。再次播放移到最前。仅保存原歌曲标识、标题、作者、封面，不保存匹配源、临时 URL、请求头和 Cookie。opaque id 原样保留，不解析或改写。

数据库位于应用支持目录的 `mix_music.sqlite`。设置与播放会话仍使用原有偏好存储，插件凭证不迁入本数据库。

“我的 → 播放历史”支持分页、重播、删除和确认清空。新播放期间已打开的历史页可手动刷新。

验证：真实 SQLite 文件测试覆盖去重、ID 类型、分页、重开迁移、独立功能迁移、清空隔离、临时字段排除和播放通知。Android/Windows 尚需设备验证；Web 还需要配置 sqlite_async 的 WASM/Worker 资源，本次不宣称已打通 Web。

## 下载记录

- `DownloadStore` 独立维护 `_download_migrations`、`download_tasks`、`download_queue`，不依赖历史或播放器。任务与队列结构在一个事务中替换，读取也使用事务。
- `DownloadSession` 负责下载模型与队列快照转换、定时保存及恢复；`DownloadController` 可选注入 Store，不注入仍可使用原内存下载流程。
- 保存任务顺序、状态、字节数、质量、匹配来源身份、文件路径、目标目录、分组方式，以及批量来源的分页游标与已加载歌曲。临时地址、请求头、Cookie 不落库；opaque id 保持原样。
- 重启不自动下载。已完成、失败、取消的状态保留；中断任务显示已取消，可点重试。批量来源恢复为挂起，点来源的恢复按钮继续后续分页。重试仍重新解析地址，已存在文件仍跳过。
- 每秒至多触发一次快照保存，切后台和正常退出再保存。任务移除或清空队列只清记录，不删除音频文件。强制结束可能丢失最近约一秒状态，但不会破坏事务中的旧记录。
- 读取失败明确显示错误并记录日志，停止启动下载，不覆盖原记录，不影响历史模块。设置仍用偏好存储。此前下载任务仅存内存，无历史记录迁移；磁盘上已有音频继续按原文件检查去重。

移除下载存储时去掉 `main.dart` 的 Store 注入和后台保存调用即可，不改历史表或数据库公共类。功能测试覆盖数据库重开、手动重试、新地址解析、批量分页继续、文件去重、损坏记录隔离、移除与清空；实际设备重启仍待验证。
