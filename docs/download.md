## 集合批量下载

在歌单、专辑、歌手或排行榜详情点击“下载全部”，按当前默认下载音质加入下载队列；控制器仍可明确指定本次音质。不为选择音质请求整个集合。

加入时只登记来源和已有结果，轮到该来源时再逐页加载，每首实际开始下载时才解析链接。选定音质用于后续各页；同一来源同音质重复加入会去重，不同音质独立处理。

下载页按原队列顺序显示来源标题与歌曲，完整加载后仍保留标题和完成/失败统计。使用列表按需构建，不靠页面滚动驱动下载。来源支持跳过、重试和取消；取消停止该来源未完成任务和后续分页，不影响其他来源、单曲或已下载文件。单独重试挂起来源中的歌曲会恢复其所属来源。

查看和执行分别触发分页：滚动接近列表末尾时，一次加载一页歌曲信息，不必等下载进度；各来源也提供“查看更多歌曲”，可提前查看后面的来源。查看不调用 `playUrl`、不提前下载音频、不移动执行游标，也不恢复已跳过的来源。与执行器共用集合分页结果及未完成请求；失败页不因滚动反复重试，取消的来源不自动展开。控制台日志为 `[Download][VIEW_PAGE]`。

集合日志增加 `COLLECTION_QUEUED / COLLECTION_SKIP / COLLECTION_CANCEL / COLLECTION_RETRY`，使用本次运行的来源标识关联事件。

## 重试和跳过

下载页面统一配置自动重试次数，默认 2 次（最多尝试 3 次），0 表示失败后直接跳过；配置通过 SP 保存。单曲和歌单分页共用该设置，失败后间隔 1 秒再尝试。

- 单曲：每次重试重新调用 `playUrl`，不复用失败链接。耗尽后保留失败任务，继续下一首。
- 歌单：重试当前失败页，耗尽后由 HyperQueue 挂起来源，继续后续单曲或歌单，不把失败当成分页结束。
- 手动重试：重置次数；分页从失败页继续，不重新下载已完成歌曲。分页成功后，下一页重新获得完整重试次数。
- 等待重试时可取消；歌单可手动跳过和恢复。跳过保留已下载文件与失败位置。
- 重试策略仅在下载控制器，播放仍默认停在失败分页，不因下载设置改变行为。

本次重试改动与相关能力共 81 项功能回归通过，静态检查通过。包含可配置 0/1/2 次、取消及释放等待、首个歌单持续失败后继续 B、成功页重置次数、恢复失败页而不重复下载已完成歌曲。未进行 UI 或平台设备实测。

当前文件默认保存到应用文档目录的 `MixMusic/downloads`；下载页面提供统一“下载目录 → 选择文件夹”入口。目录与分类在加入任务时确定，切换设置仅影响新加入的任务，不移动已有文件。目录设置已通过 SP 保存，任务暂不持久化，不承诺退出后续传。移除任务保留文件，不提供隐式删除文件行为。

## 完整缓存转正式下载
