# 收藏状态

歌曲、歌单、专辑、歌手、视频统一提供 `bool? favorited` 与 `bool? locallyFavorited`。`null` 为未知，`false` 为明确未收藏，两者独立。

- 平台状态由插件提供；收藏列表可以直接确认已收藏，自建歌单不等于已收藏。
- 本地状态保留在实体序列化中，仅由宿主维护；数据库尚未实现，默认未知。
- MusicApi 调用边界不发送本地收藏状态，也不接受插件覆盖。资源的动态 ID 原样保留。
- 收藏操作成功后更新传入实体的 `favorited`，失败不修改；当前没有跨对象快照的全局广播。
- “我的”页面只负责交互确认，收藏/取消收藏与歌单操作交给 `LibraryController`。操作完成后只失效对应平台和分类的列表缓存，不刷新或跳转到用户刚切换的其他平台/分类。
- 收藏状态补充属于具体插件的内部实现，不是宿主公共 API，不要求其他插件实现辅助导出。宿主只使用普通歌曲接口返回的 `favorited`。
- 宿主账号业务只使用无参 `getAccount()` 和插件登录流程，不再提供 Cookie 读写、平台会话刷新、网页登录地址及旧用户信息辅助方法。这些操作留在插件内部；旧协议测试只使用专用内存包访问，不恢复生产导出。
- 未确认的其他资源状态查询暂不猜测；视频接口仍待验证。
- 插件自行在搜索、首页歌曲、歌单/专辑/歌手/排行榜歌曲、每日推荐接口内部补充状态；请求顺序、鉴权、批查和失败处理不泄漏到页面或通用控制器。
- 集合统一使用 `loadMore()`，不区分查看、播放或下载；三者拿到相同歌曲契约，不需要记住额外查询步骤。
- 普通专辑详情仍使用既有收藏子响应，普通 MV 详情使用原响应状态。其他资源不会把收藏数、权限字段当作用户状态。详见插件仓库文档。
