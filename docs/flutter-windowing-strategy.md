# Flutter 多窗口采用策略

更新时间：2026-10-14

## 结论

新版主线继续使用 Flutter stable，不为了多窗口切换到 `main`。

桌面歌词、小窗播放、桌面背景等属于后期能力，先不作为新版首发的硬依赖。等 Flutter 多窗口进入 stable 后再正式接入。

如果需要提前验证，可单独建立实验分支，使用 Flutter `main` 和 `--enable-windowing` 做原型，不让实验 API 进入正式主线。

## 原因

- 本地 Flutter 3.47.7 stable 已包含多窗口相关实现和示例，但功能开关仍只对 `main` 通道开放。
- Flutter 官方仍将 Windowing API 标记为实验性，接口可能变化，不建议用于生产应用和已发布插件。
- 官方示例仍需导入 Flutter 内部实现，升级成本和破坏性变化风险较高。
- 新版首发平台是 Android、Windows 和车机，真正依赖桌面多窗口的主要是 Windows 后期功能，不值得让整个项目承担开发版风险。

## 代码约束

- 业务、播放状态和页面状态不依赖具体窗口对象。
- 窗口能力只保留一个很薄的平台入口，需要时再实现，不提前设计复杂窗口框架。
- Android 小窗、画中画和悬浮能力按 Android 平台能力处理，不与桌面多窗口强行统一。
- 任务栏歌词、透明置顶、鼠标穿透、桌面背景等可能仍需要 Windows 原生实现，不默认认为 Flutter 多窗口 API 可以全部解决。

## 重新评估条件

满足以下条件时再考虑正式接入：

1. Windowing API 对 Flutter beta 或 stable 开放。
2. 不再依赖 `package:flutter/src/...` 等内部接口。
3. Windows 上窗口位置、尺寸、置顶、透明和生命周期能力可以满足歌词窗与小窗需求。
4. 多窗口下播放、歌词动画和状态共享没有明显性能问题。
