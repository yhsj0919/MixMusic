# 音乐缓存

入口：设置 → 存储与缓存。默认开启，容量 512 MB，设置与完整文件索引跨启动保存。

业务由全局 `PlayerController.cache` 持有，页面只调用 `setEnabled`、`setLimit`、`clear`。播放解析统一经过 `cache.resolve`，不依赖具体页面。

缓存键为 `pluginId + 原始动态 ID + 音质` 的规范化摘要，对象键排序，字符串和数字 ID 不混用。音质分别保存；命中后跳过插件播放地址解析，歌词仍走独立流程。

未命中时，本机转发服务复用播放器当前 HTTP 请求，一边转发一边写入临时文件；收到完整数据后才登记为可复用缓存。不额外下载整首，也不扫描整个歌单。MPV 正常预读可能在歌曲播完之前收齐文件。

## 日志判断

控制台搜索 `[MusicCache]`，也可在缓存设置中“查看缓存日志”。日志不打印远程 URL、请求头和凭据。

- `RESTORE`：恢复设置及有效完整文件。
- `MISS → PROXY → WRITE_START → WRITE_COMPLETE`：未命中、正常转发、开始写入、完整写入成功。
- `HIT`：直接播放本地缓存，跳过 `playUrl` 和网络音频请求。
- `COPY_START / COPY_COMPLETE`：复制完整缓存至下载临时文件，原缓存保留。
- `COPY_CANCELLED / COPY_INVALID / COPY_UNAVAILABLE`：复制取消、缓存无效或不可用；取消不发起网络下载。
- `BYPASS`：缓存关闭或资源不支持，仍正常交给播放器处理。
- `SKIP_WRITE`：本次请求不能形成完整缓存，附方法、状态码、长度与类型。
- `TRANSFER_STOP / WRITE_DISCARD`：传输中断或临时文件作废，不登记完整缓存。
- `UNAVAILABLE / WRITE_ERROR / INDEX_ERROR`：缓存或索引不可用；检查日志，播放尽可能继续。
- `EVICT / CLEAR / SETTING`：容量淘汰、手动清理、设置变更。

## 首版范围

支持 HTTP/HTTPS、已知长度的完整音频响应（200，或覆盖整个文件的 206）。暂不缓存部分 Range、未知长度、HLS/DASH；不做分片合并或断点续传。超过上限的单文件不写入。

文件位于应用支持目录的 `music_cache`，与本地音乐及正式下载分开。按最近使用淘汰；当前播放文件保留，手动清理时会在日志提示仍有保留项，可停止后再次清理。大小校验不等于内容哈希校验。
