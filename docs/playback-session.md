# 播放队列与进度恢复

2026-10-22：由全局 PlayerController 持有 PlayerSession，不依赖播放页面，不初始化播放器来恢复状态。

- SP 的 `playbackSession` 保存版本化快照：队列树、当前索引和歌曲、播放进度、上次总时长。播放模式沿用已有 `playMode` 设置。
- 单曲的来源、opaque ID、元数据、已选音质与匹配资源身份保留；歌曲和音质中的临时 URL、请求头不保存。opaque ID 原样保留，不改其中的字段。
- HyperQueue 保留集合分组、分页位置、已读取歌曲、插入/删除后的顺序与暂停来源，不把未加载完的歌单展平成已结束列表。恢复不发起分页请求，之后按既有队列逻辑续载。
- 重启只恢复展示状态，默认暂停，不解析播放地址、不获取歌词、不创建 MPV。点击继续时，重新走现有地址解析/缓存流程并传入进度，同时独立获取当前原歌曲的歌词；本地音乐通过原始 file/content ID 重新解析。首次继续不再把尚未加载的歌词当作已有歌词而跳过请求。
- 歌曲和队列变化合并 300 ms 保存；播放进度每 5 秒最多保存一次。暂停、清空、进入后台及正常销毁时立即保存，写入按顺序提交。系统强杀时可能丢失最后约 5 秒进度，SP 不作为强制终止下绝对可靠的数据保证。
- 清空后不会恢复旧队列；损坏或不匹配的快照记录日志并忽略，不阻塞启动。缺失插件或失效本地授权在继续播放时由原有接口报错，不在恢复时自动跳过、换源或出声。

不恢复定时任务，不等同于历史记录、收藏或用户歌单数据库。歌词继续从全局独立歌词流程获取；随机播放保留模式，不保存随机数状态和跨启动“上一首”的历史栈。

验证：新增队列/进度暂停恢复、地址/请求头清理、opaque ID 保留、匹配身份、惰性集合续页和删除保留、清空与损坏快照功能测试，连同队列、播放、设置和歌词合计 40 项回归通过；静态检查通过。未构建、未打包，Windows/Android 实际重启、后台强杀和重新播放仍待用户验证。
