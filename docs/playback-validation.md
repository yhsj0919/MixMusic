# 单曲播放验证

更新：2026-10-15。

MPV 适配边界支持把标准 data URI 转为 MPV 内存协议，外部离线示例可提供程序生成的 WAV，不需要宿主内置音频或访问远端音源。已用完整示例验证实际解码。

首页点击歌曲后选择音质，PlayerController 通过 mpv 的 SourceResolver 在真正加载时调用插件 playUrl，传递动态歌曲 ID、已选音质和插件返回的 HTTP 请求头。

系统媒体控制只由 lemon_audio 处理，mpv 自带媒体会话不启用。首次播放才创建引擎，启动页面不依赖音频初始化成功。

底部播放区域与横屏平板播放器区域共享状态，支持播放/暂停、进度显示和跳转，显示实际返回的音质。歌词由 lrc 独立请求，失败只记日志，不阻塞播放；本轮仅获取歌词数据，尚未接入正式歌词渲染。

播放解析、初始化和引擎错误进入插件日志；地址为空时仅提示“音源未返回可播放地址”，宿主不推测登录、会员或音质等原因。具体业务错误由插件明确返回。

已验证：Windows Debug 构建、页面回归；原生 MPV 使用本地测试音频与空音频输出，验证加载时解析、HTTP 请求头设置、解码、暂停、跳转后恢复播放。

Android Debug APK 构建通过，已配置后台媒体服务、媒体按键接收器、网络与前台播放权限，Activity 使用 AudioServiceActivity，最低 Android 版本为 7.0。针对本机工程与 pub 缓存位于不同盘符导致的 Kotlin 增量缓存错误，宿主 gradle.properties 关闭了 Kotlin 增量编译。

用户已确认 Windows 与 Android 插件歌曲播放正常；系统媒体按键仍待实机验收。

自动续播修复：旧曲 EOF 状态可能在新曲加载时仍然可见。原适配层先 `open(play: false)` 再 `play()`，会误对旧 EOF 状态执行 seek，导致 seek 失败并中断播放。现在适配层先暂存新媒体，在 lemon_audio 发出播放请求后用 `open(play: true)` 一次提交加载与播放意图；只有重播当前已结束歌曲时才 seek。未修改音频依赖。

已增加真实 MPV 回归：带延迟解析的三首曲目依次自然结束后继续播放，并验证最后一曲重播。与随机队列、结束事件去重及播放错误处理合计 12 项功能测试通过，不进行 UI 验证。

MPV 原生测试需先生成 Windows 构建产物，再运行 `flutter test test/mpv_playback_test.dart --dart-define=MPV_SMOKE=true`；测试音频取自本地 lemon_audio 示例。普通回归不运行原生播放或真实联网测试。

2026-10-21：用户澄清清空列表后重播时音频仍在播放，问题是进度条不更新，播放状态切换正常。此前针对停止回调的播放修复、附带诊断和新增测试已按要求撤回，不作为此问题的解决方案；进度条问题待单独排查。

进度条修复：真实 MPV 测试已复现第二次播放同一音频时，位置持续推进但控制器总时长仍为 0。MPV 未重复通知相同 duration，而清空/换曲已将控制器 duration 归零。现在在 ready 状态按 MPV 当前快照补齐总时长，仅数值变化时更新系统媒体时长，不改变播放/暂停控制。新增 `player_progress_test.dart`：修改前第二次播放断言失败，修改后通过；另有 18 项队列/控制器/缓存回归通过，静态检查通过。桌面可执行文件尚未重建、用户端复测及 Android 待验证，不进行 UI 验证。

播放全部修复：原先追加歌单时首曲已在队列，会被全局去重跳过，歌单起点因而变成第二首。播放全部现在替换为该歌单（保留 HyperQueue 按需加载），当前歌曲就是首曲时只更新队列定位、不重新解析或重置进度；否则从首曲开始。普通“加入播放列表”仍为追加。新增三项控制器回归，与 HyperQueue 合计 20 项通过，静态检查通过；客户端端到端待用户验证。
