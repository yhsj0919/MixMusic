# 宿主与插件边界检查

2026-10-20：检查评论、完整列表筛选、搜索、排行榜、首页、收藏和音质入口，按“宿主只定义功能大类，插件定义小分类与具体数据”处理。

## 本轮修正

- 评论：分类、名称、默认项由 songComments 结果提供；无分类不补默认按钮，分类 ID 和游标保持不透明，不增辅助接口。
- 完整列表：移除“所有歌手列表都组合筛选”的特例，不在宿主按分组 ID 拼平台请求字段，也不把对象 ID 转成字符串。
- 插件分类分组可声明 `independent:true`，表示该分组与其他分组独立选择。宿主只保存 `{filters:[{group:<原始分组ID>,value:<原始选项对象>}]}`；同一组替换选项，不同组保留。插件负责把选择转换成请求参数。
- 未声明 independent 的分组仅用于展示层级，选择叶子后原样传递原选项；歌手、专辑、歌单、MV 同样处理，不因资源大类改变分类语义。
- 重置筛选传 null 并显示“默认”，不将插件默认结果直接称为“全部”。

没有新增分类请求、没有对所有列表强制引入组合筛选，也没有变更音频评论。当前 QQ 插件版本 2.0.25 负责声明歌手独立分组及实际字段转换；普通单分类示例插件无需修改。

## 检查后保留

- 搜索歌曲 / 专辑 / 歌手 / 歌单 / MV、收藏的业务大类和播放模式属于宿主功能。
- 全局播放 / 下载音质预设是跨来源的宿主偏好，不改；具体可用音质列表与显示标题仍来自插件。
- 其他分类名称、榜单分组内容已经来自插件，不另造固定分类。

## 验证

18 项宿主纯功能回归通过：列表、评论、排行榜、搜索业务；独立插件的筛选字段转换、评论分类及 ZIP 安装验证通过，静态检查通过。覆盖无分类、普通歌手分类、跨资源大类组合筛选、数字 / 对象分组 ID、默认项及切换状态。

过程中误运行旧搜索 UI 用例，其中“点歌曲后必须弹音质选择”的历史断言失败；没有为迁就该断言改变当前播放行为，已单独通过搜索业务回归。本轮不将旧 UI 用例算作已通过，也未新增视觉验证。
