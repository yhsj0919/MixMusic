## 当前版本（QQ 插件 2.0.6）

- 插件直接通过官方接口获取并展示 QQ、微信二维码，自动串行轮询（每次完成后间隔 2 秒），展示待扫码、待确认、成功、过期与取消状态；提供手动刷新，异常不无限重试。切换方式及页面隐藏/释放时停止后续轮询。
- QQ 授权跳转保留 Cookie 并交换授权码；微信独立提取 UUID、轮询 code，再交换音乐会话。凭据只留在插件侧，不交给宿主解析。
- 账号密码在插件独立表单输入，提交到受限的官方 QQ 认证页，由官方环境执行密码加密及验证码；这是插件表单 + 官方认证环境，不是纯 HTTP 密码协议实现。出现验证码时由用户完成，再点“已完成验证，获取登录状态”。不将密码发送给宿主音乐 API，不保存密码，提交及页面离开后清除插件页面中的密码。
- Cookie 输入、网页登录保留为备用入口；所有遮挡输入框显式设置 `maxLines: 1`。
- 密码提交仅允许当前网页为 `xui.ptlogin2.qq.com`；扫码授权仅访问 HTTPS 官方 QQ 域名，不执行服务端返回的脚本，不向外部域名转发凭据。
- 6 项扫码/授权链测试、4 项交互状态功能测试和 6 项原有插件离线测试通过；两种二维码的真实网络获取在 QuickJS 运行时通过，未使用账号密码。扫码确认后的真实会话、账号密码、验证码及 Android/车机仍待用户测试。不做 UI 布局/截图测试。
- 上述实现和测试只在独立插件仓库；宿主沿用原有统一登录入口，无需新增平台分支。
- 2.0.6 已覆盖安装到本机 Windows 测试应用，保留用户数据，无需重编译宿主。扫码授权的临时 qrsig、p_skey 等只保留在内存，不随音乐会话保存。

## 初版实现记录（2.0.4）

- 插件声明登录 JSUI route 和 `uiExports`；页面只能调用同插件明确公开给 UI 的方法。
- 宿主接入现有 `lemon_js_ui_webview`，安装与重启恢复时注入 WebView 能力；未修改 Lemon 库或 WebView 依赖源码。
- QQ 登录实现、域名、凭据判断和专用测试只在独立插件仓库。2.0.4 提供 Cookie 输入和内嵌官方网页登录；QQ/微信扫码在官方页面选择，二维码生成、轮询和过期刷新由官方页面处理，不是独立二维码协议实现。
- 网页完成登录后，由用户点击“保存并校验”；插件读取 Cookie，调用自身账号接口校验后保留会话。失败恢复原 Cookie，宿主不推测原因。
- 插件日志只记录校验成功/失败和退出等事件，不打印 Cookie、Token 或完整登录响应。默认 KV 为 SharedPreferences，尚不提供凭据加密保证。
- 退出只清除当前插件保存的会话，不调用 WebView 全局清 Cookie，避免影响其他插件。网页自身会话需在官方页面退出；WebView bridge 隔离不等于原生浏览器 Cookie 容器隔离。
- 本轮不提供独立账号密码/短信接口；官方网页若提供可在网页操作。外部浏览器 OAuth、第三方 App 授权和相机扫码均不在本轮。

## 测试步骤

1. 完全退出旧应用，重新运行原生构建（新增 WebView 不能只热重载）。
2. 在插件管理安装独立仓库提供的 QQ 2.0.4 ZIP，点击“登录”。
3. 选择网页登录，在网页内点击登录并切换 QQ/微信扫码；登录完成后点“登录完成，保存并校验”。
4. 返回每日推荐，手动刷新，确认已使用插件保存的会话。
5. 可单独测试 Cookie 输入、错误 Cookie 不覆盖旧会话、重启保留及退出登录。
