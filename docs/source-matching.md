# 音源匹配方案

2026-10-21：首版已实现，真实插件与设备端匹配仍待用户验证。

## 匹配流程

遵循 v1 的大致流程：优先原音源，按用户选择的匹配音源搜索候选，筛选后获取可播地址，按音源优先级选择。
增加独立评分工具类，负责信息规范化、相似度与候选排序；不把评分逻辑堆进请求和播放代码。
评分工具为 `common/plugin/song_matcher.dart`，编排为 `common/plugin/source_matcher.dart`；请求 API 与播放控制器不承担评分逻辑。

首版参数：歌名 70、歌手 30，最低 85 分自动尝试；歌名相似度低于 .85、已知歌手相似度低于 .8、Live/伴奏/翻唱/Remix/加速等版本类型冲突直接排除。歌手缺失时仅按歌名计算；无时长字段，不推测或额外请求时长。比较时统一全半角、大小写和标点，原元数据不变。

播放匹配默认关闭。原音源返回空地址或抛异常时才匹配，不判断会员、登录、版权字段。各已选音源并行搜索第一页 20 条，保留音源设置顺序；每个音源内评分排序，最多尝试 3 个高分候选，失败隔离。下次先尝试原音源，再尝试已有匹配关联。

设置入口：设置 → 音源匹配。可启停、选择音源并用箭头排序。只有启用且提供搜索、播放地址的音源参与自动匹配。开关与音源顺序通过 SP 保存。

候选入口：播放页右上角“音源候选”。显示平台、歌曲、歌手与评分，复用自动匹配搜索结果，不为展示再次搜索；手动列表包含低分结果，允许明确选择，也可以选择原音源。提供显式“重新搜索”，不自动轮询。音质变化复用同一歌曲候选列表。手动切源保留进度和暂停状态，不替换原歌曲或队列身份；歌曲已切换时旧弹窗不能改动新曲。

原歌曲身份与实际播放来源分开保留，不改变收藏归属。

## 下载

- 当前正在播放的歌曲：原音源不可播、正在使用匹配音源时，默认下载当前实际听到的匹配版本。
- 批量下载：优先原音源；原音源失败后是否允许匹配，由独立下载设置控制，默认关闭。
- 下载执行时重新获取地址，不复用播放时的旧链接。
- 保留原歌曲身份，记录实际下载来源和音质。
- 当前播放版本下载失败时不静默换成另一版本。

## 缓存

- 缓存键按实际来源：实际插件 ID + 实际歌曲 ID + 实际音质。
- 匹配音频不冒充原音源缓存；原歌曲另外保留匹配关联，不替换缓存身份。
- 下载当前匹配版本时，按实际来源查找完整缓存，命中后直接复制为正式下载文件。
- 下次从原歌曲播放，先尝试原音源；不可播时，再通过匹配关联查找对应来源的缓存。
- 音质变化时使用相应音质的缓存键，不混用。

`Song.matchedSong` 保存当前实际来源，`actualSong` 用于实际音源操作；插件调用会剥离宿主的 matchedSong 字段。临时切换音质作用于实际来源，UI 显示实际返回音质。

匹配关联和搜索候选目前保存在内存，不存过期 URL；重启后会重新搜索，实际来源缓存文件仍保留。关联持久化尚未接入，不宣称支持跨重启免搜索。
